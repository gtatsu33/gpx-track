耐久レース チーム位置共有アプリ 機能仕様書
作成日：2026-11-02（2026-11-03 更新）　対象バージョン：APP_VERSION 1.1.1

■1. 概要
- アプリ名：gpx-track（画面の表示も小文字・ハイフンの「gpx-track」）
- 用途：チーム対抗の耐久レース（自転車の7時間エンデューロなど、数人が交代で走るリレー形式）で、次のことを行う
  - チームメンバーの現在地をマップで共有する
  - チーム通算の周回数とラップタイムを自動で計測する
  - 定型チャットでやり取りする
- 1ルーム＝1チーム
- 対象端末：スマートフォンのブラウザ（iOS Safari 18.4以降、Android Chrome最新）。縦画面専用
- 利用形態：Safariで直接開くことを推奨する（iOSのホーム画面PWAではWake Lockが効かない可能性があるため）
- 公開先：Cloudflare（HTTPS）

■2. 用語
- オーナー：ルームを作った人。オーナーパスコードを知っている人だけがなれる。名簿の1人（オーナーのライダー）として扱う
- オーナーモード：今のライダーがオーナーのライダーになっている端末の状態。オーナー用の操作ができる
- ルーム：1チーム分の部屋。6桁の参加コードで参加する
- 端末：アプリを開いているスマホ（匿名ユーザー）。メンバーと同じ意味で使う
- 名簿（ライダー）：ルームごとの走る人の一覧。端末とは別に持つ。1台の端末を複数人で交代して使ったり、端末を持たない人が走ったりできるようにするため
- この端末のライダー：その端末で今走っている人。端末ごとに1人を名簿から選ぶ。同じライダーを複数の端末で同時に選んでもよい
- コントロールライン：周回の判定に使う線。オーナーがマップ上で2点を指定して作る
- 通過：誰かの端末がコントロールラインを越えたこと。チーム全体で1回の通過につき1周が記録される
- 判定速度：「走っている」とみなす速度。ルームごとにオーナーが設定する（初期値は15km/h）
- 走行状態：各メンバーの端末がGPSの速度から判定する「走行中」か「ピット」か
- 走行距離：判定速度以上で移動した距離。ピットで歩いたりした距離は含めない
- ラップのライダー：その周の間に走行距離が最も長かったライダー
- 現在のライダー：今「走行中」の端末のライダー（いなければ最後に通過したライダー）

■3. 画面
3.1 名前登録（初回のみ）
- 案内文「チーム内であなたを識別するための名前を入力してください。」を表示する
- 名前（1〜20文字）を入力して「はじめる」を押す。入力欄には例（「例：佐藤」）を薄く表示する
- 入力欄の下に、次の補足を小さく表示する
  - 入力した名前は、マップの名前ラベル、ラップ表、チャットに表示されること
  - あとから変える場合は、ルームに入って ⚙ メニューの「名前の変更」から変更できること
- 裏で匿名サインインを行い、名前をプロフィールに保存する。2回目以降は自動でログインする
- 名前は端末にも保存しておく。起動したときに、サーバーからユーザーが削除されていたら（データの一括削除のあとなど）、端末に残ったログイン情報を消し、保存した名前で自動で入り直してホームを表示する
  - 前回開いていたルームと、送れずに残っていた通過・距離のデータは消す
  - 名前が保存されていなければ、名前登録の画面を表示する
  - 圏外などで確認できなかったときは、何もせずにそのまま使う
- ここで登録した名前は、ルームに参加したときに自動で作る「本人のライダー」の名前に使う
- ルームの中の名前（この端末のライダーの名前）は設定メニューで変更できる。変更する前に送ったチャットの名前は書き換えない（ラップ表とマップは今の名前で表示する）

3.2 ホーム
- 「参加コードで参加」：6桁のコードを入力して参加する。大文字と小文字は区別しない。紛らわしい文字（O/0/I/1）はコードに使わない
- 「ルームを作成（オーナー）」：ルーム作成画面へ進む
- 「オーナー権限の復帰」：参加コードとオーナーパスコードを入力すると、ルームに参加して、この端末のライダーをオーナーに切り替える（ブラウザのデータが消えて別人扱いになったとき用）
- 参加中のルーム一覧：タップするとルーム画面に戻る
- 画面下に APP_VERSION を表示する

3.3 ルーム作成（オーナー）
- 入力項目
  - オーナーパスコード（必須）
  - チーム名（必須、1〜30文字）
  - レース時間（任意、時間と分）
  - 最小ラップ秒数（初期値30、10〜600）
  - 判定速度（初期値15km/h、3〜100）
- パスコードが間違っていたら「パスコードが違います」と表示する
- 作成に成功したら参加コードを大きく表示し、コピーボタンを付ける。そのままルーム画面へ進む
- コントロールラインはルーム画面のオーナーメニューから設定する

3.4 ルーム画面（メイン）
 ┌ヘッダー───────────────────────┐
 │ チーム名     経過 3:12:45 / 残 3:47:15 │
 │ 128周   🚴佐藤   ☀(WakeLock)        ⚙ │
 ├タブ─────────────────────────┤
 │    マップ     │     ラップ           │
 ├コンテンツ（タブで切り替え）─────────┤
 │                                    │
 ├チャット表示エリア（約4行、スクロール）─┤
 ├定型ボタン─────────────────────┤
 │ [  もう一周いく  ] [ ピットインする  ] │
 └──────────────────────────┘
- ヘッダー、タブ、チャットエリア、定型ボタンは常に表示し、真ん中のコンテンツだけをタブで切り替える
- 経過時間はレース開始からの時間。レース時間が設定されていれば残り時間も表示する
  - レース開始前は「スタート前」、終了後は「レース終了」と表示する
- 周回数はチーム通算
- 🚴の横に現在のライダーの名前を出す。自分の端末が「走行中」のときは、自分の名前に「走行中」バッジを付ける
- その下に小さく「この端末：◯◯」（この端末のライダー）を出す。オーナーモードのときは「オーナー」バッジを付ける
- 🚴の部分をタップすると、ライダーの切り替え（3.9）を開く
- Wake Lockの状態：有効なら☀、無効か未対応なら⚠を表示する（タップすると説明が出る）
- ⚙ で設定メニューを開く（オーナーには、オーナー用の項目も表示する）

3.5 マップタブ
- OSMの標準タイルを使い、右下に「© OpenStreetMap contributors」を常に表示する
- 端末ごとに色分けした丸いマーカーと名前ラベル（その端末のライダーの名前）を表示する
  - 現在のライダーは大きいマーカーで強調し、直近60秒の軌跡を線で表示する
  - それ以外の「走行中」のメンバーは、通常サイズのマーカーに枠線を付ける
  - 30秒以上位置が更新されない、またはオフラインのメンバーはグレーで表示する
- コントロールラインを赤い線で表示する
- 地図上のボタン：「全員表示」（全員のマーカーが入るようにズーム）、「ライダー追従」のオン/オフ（初期値はオン）

3.6 ラップタブ
- 表の列：周回 ／ 通過時刻 ／ ラップタイム ／ 名前
  - 周回：チーム通算の番号（1から）
  - 通過時刻：端末のローカル時刻で HH:MM:SS
  - ラップタイム：1時間未満は m:ss.s、1時間以上は h:mm:ss.s
  - 名前：ラップのライダー（その周で走行距離が最も長かった人。5.4を参照）
- 新しい周を上に表示する。全周で最速のラップには★を付けて強調する
- 表の上にサマリーを表示する：総周回数、ベストラップ（タイムとライダー）、平均ラップ
- 名前がまだ確定していない周（通過の直後で、距離のデータを待っている間）は名前を薄く表示する
- オーナーモードの端末で行をタップするとメニューが開き、次の操作ができる
  - 周の削除（誤検知の取り消し。以降の周番号とラップタイムは自動で再計算する）
  - 名前の修正（名簿から選ぶ。オーナーには「(オーナー)」を付けて表示する。自動判定より優先する。「自動に戻す」もできる）

3.7 チャット
- 表示エリアには直近50件を「名前: 本文　HH:MM」の形式で表示する。新着が来たら一番下までスクロールする
  - 名前は、送った時点のその端末のライダーの名前
- 定型ボタン「もう一周いく」（左）と「ピットインする」（右）は、高さ56px以上の大きめのボタンにする
  - 押したらすぐ送信する。誤送信を防ぐため、同じボタンは2秒間押せないようにする
  - 今回は編集機能を付けず、自由入力もできない
- システムメッセージ（グレー表示）を自動で投稿する
  - 「レース開始」「レース終了」
  - 「ライダー交代：◯◯」（前の通過と違うライダーがラインを越えたとき。ライダーの切り替え操作では出さない）

3.8 設定メニュー（⚙）
- 全員
  - この端末のライダー：今のライダーの名前（オーナーなら「(オーナー)」付き）と「切り替え」ボタン（3.9を開く）
  - 名前の変更：この端末のライダーの名前を変える。名簿の中で同じ名前は付けられない
  - 参加コードの表示とコピー、ルームから退出、アプリのバージョン
- オーナーモードの端末だけ
  - コントロールラインの設定：マップを2回タップして端点A・Bを指定し、プレビューを見てから保存する。「コースの幅より左右に少し長めに引いてください」と案内を出す
  - レース開始：開始時刻を「今」にして、状態を「レース中」にする
  - 開始時刻の修正：時刻を入力して変更する（1周目のラップタイムを再計算する）
  - 手動で通過を記録：時刻を入力して1周を追加する。初期値は今の時刻。GPSが取れなかった周を補うためのもの
  - 判定速度と最小ラップ秒数の変更
  - レース終了：状態を「終了」にし、それ以降はラップを記録しない
- アプリ内の確認やメッセージは、ブラウザの alert や confirm を使わず、アプリ内のモーダルで出す

3.9 ライダーの切り替え（この端末のライダー）
- 名簿を一覧で出す。オーナーを先頭にし、名前の後ろに「(オーナー)」を付ける。今のライダーは強調する
- オーナー以外を選ぶと、パスコードなしですぐ切り替わる。オーナーモードだった端末は、通常モードに戻る
- オーナーを選ぶと、オーナーパスコードの入力を求める。正しければ切り替わり、その端末がオーナーモードになる
  - ルームを作った端末でも、オーナーに戻すときは毎回パスコードを入力する
- 「ライダーを追加」：名前（1〜20文字）を入力して名簿に追加し、そのままこの端末のライダーにする。名簿の中で同じ名前は付けられない
- ルームに参加すると、登録した名前で「本人のライダー」を自動で作り、この端末のライダーにする
  - 名簿に同じ名前の人（オーナー以外）がいれば、新しく作らずにその人を使う（先に名簿へ追加されていた人が、あとから自分の端末で参加したとき用）
  - 同じ名前がオーナーなら、末尾に数字を付けた名前で作る
- 1人1台で使う場合は切り替えなくてよく、今までと同じ使い方になる
- 名簿からの削除と並べ替えは、今回は作らない

■4. 位置共有と走行状態
- 位置はブラウザの Geolocation API（watchPosition、高精度モード）で取得する
- 精度が30mより悪い測位は使わない
- 走行状態は各自の端末で判定する
  - 判定速度以上が10秒続いたら「走行中」にする
  - 判定速度未満が30秒続いたら「ピット」にする
- 位置の送信間隔：「走行中」なら5秒ごと、「ピット」なら10秒ごと（電池、通信量、Supabaseの無料枠を節約するため）
- GPSの測位、通過の判定、走行距離の計算は、送信間隔とは関係なく端末の中で約1秒ごとに行う（ラップタイムの精度は送信間隔の影響を受けない）
- 位置はサーバーに保存せず、リアルタイム配信だけで共有する
- 走行距離（判定速度以上で移動した距離）は、10秒ごとにまとめてサーバーに記録する（ラップのライダー判定に使う）
- ルーム画面を開いている間だけ動く。画面を閉じたり別のアプリに切り替えたりすると止まる（Webアプリの制約）
- 前提：走るメンバーはスマホを身につけるか車体に固定し、アプリを開いたままにする

■5. ラップ計測
5.1 通過の判定（各メンバーの端末が、自分の通過だけを判定する）
- 1つ前の測位点Pと今回の測位点Qを結んだ線分が、コントロールラインABと交わったら「通過」とする
  - GPSの誤差を考えて、ABは両端をそれぞれ15m延長して判定する
  - PとQの間が20秒を超えている場合は判定しない（GPSが途切れたあとの誤判定を防ぐため）
  - PからQまでの平均速度が判定速度より遅い場合は通過としない（ピットでラインのそばを歩いている人を除くため）
  - 通過の向きは問わない
- 通過時刻は、PとQの時刻を交点の位置の割合で線形補間して求める
- 判定は全員の端末で常に行う。走るのは常に1人なので、通過するのは基本的にその人の端末だけになる

5.2 記録（サーバーで確認する）
- 次の条件をすべて満たしたときだけ記録する
  - レース中である
  - 記録しようとしている端末がルームのメンバーである
  - 通過時刻がレース開始時刻より後である
  - チームの前回の通過から、最小ラップ秒数以上たっている
  - レース開始時刻から、最小ラップ秒数以上たっている（スタート地点がラインの直前にあり、スタート直後にラインを越えた場合に1周と数えないため）
- 通過には、通過した瞬間のその端末のライダーを記録する。走行距離も、そのときの端末のライダーの分として記録する
- ライダー交代のときに2人の端末が続けてラインを越えても、最小ラップ秒数より短い間隔の2回目は記録しない（先に記録された方が有効）
- 通信エラーで送れなかった通過は端末に保存しておき、自動で再送する（同じ通過は二重に記録しない）

5.3 周番号とラップタイム
- サーバーには通過時刻だけを保存し、周番号とラップタイムは表示するときに計算する。削除や開始時刻の修正をしても、常に正しい値になる
- 第n周のラップタイム＝第n周の通過時刻－第(n-1)周の通過時刻（1周目はレース開始時刻から）
- ライダー交代を挟んだ周は、ピット作業の時間も含んだ値になる（耐久レースでの実際の周回時間）

5.4 ラップのライダー（名前）の決め方
- 判定はライダー（名簿）単位で行う。同じ端末を交代で使っても、ライダーごとに分かれる
- その周の間（前の通過から今回の通過まで）に、走行距離が最も長かったライダーをラップのライダーとする
  - 例：Aが周の途中でピットに入り、Bが出て行ってラインを越えた場合、その周で長く走った方の名前になる
- 走行距離が同じ場合や、誰の距離データもない場合（GPSの不調や手動で記録した周など）は、ラインを越えたライダーの名前にする
  - 手動で記録した周は、その時刻の直前に通過したライダー（いなければ最後に通過したライダー、それもいなければオーナー）の名前にする
- オーナーが名前を修正した場合は、その名前を自動判定より優先する
- 距離のデータは最大10秒遅れて届くため、通過の直後は暫定の名前を出し、データがそろったら確定した名前に更新する

■6. Wake Lock
- ルーム画面を表示している間、画面を点けたままにするよう要求する
- 画面が非表示になると解除されるので、表示に戻ったときに取り直す
- 未対応か失敗した場合は⚠を出し、「画面を手動で消さないでください」と案内する

■7. 制約と注意事項
- 電源ボタンを押して画面をロックしたり、別のアプリに切り替えたりすると、位置の送信、通過の判定、走行距離の記録が止まる。抜けた周はオーナーが手動で補う
- 匿名ユーザーの情報は端末のブラウザに保存される。ブラウザのデータを消すと別人扱いになるので、参加コードで入り直す（オーナーは「オーナー権限の復帰」を使う）
- Supabaseは無料プランで使う。7時間レースなら、5人のチームで月25回程度、10人のチームで月7回程度までが目安（implement.txt 3.7）
- Supabaseの無料プランは、1週間使わないとプロジェクトが一時停止する。レース前に必ずダッシュボードで状態を確認し、止まっていたら再開する

■8. 今回は作らないもの
- 定型ボタンの編集、自由入力のチャット
- 他チームとの順位比較
- ラップタイムの直接編集（削除、手動追加、名前の修正のみ対応する）
- オフライン地図、プッシュ通知
